**SSH Brute-Force Log Analyzer**

A small Python project that simulates SSH authentication logs and detects brute-force patterns by counting failed logins per source IP address.

All data is simulated. The log is generated by a script, uses reserved documentation IP ranges for the attackers, and contains no real-world data.

**What it does**
generate_auth_log.py creates a realistic auth.log file (500 lines) containing random IP addresses and a mix of Failed password and Accepted password events. Three "attacker" IPs are weighted to fail repeatedly, so there is a pattern to find.
analyze_auth_log.py parses that log, filters Failed password entries with the re module, aggregates failures per IP using a dictionary, and prints a ranked report. IPs at or above a threshold are flagged as suspected brute force.

**Project structure**

├── generate_auth_log.py   # Step 1: builds the sample auth.log

├── analyze_auth_log.py    # Step 2: parses the log and prints the report

├── auth.log               # Generated sample data (created by step 1)

└── README.md

**Requirements**

Python 3.8 or newer
No third-party packages (standard library only: re, sys, random, datetime)
How to run

Run the generator first, then the analyzer.

bash
python3 generate_auth_log.py
python3 analyze_auth_log.py

On Windows, use python or py instead of python3.

You can also analyze any other log file by passing its path:

bash
python3 analyze_auth_log.py /path/to/auth.log

**How it works**

Log format

Lines mimic real OpenSSH entries in /var/log/auth.log:

Nov 16 00:03:54 webserver01 sshd[2739]: Failed password for invalid user postgres from 192.0.2.99 port 37805 ssh2
Filtering with re
python
FAILED_RE = re.compile(
    r"Failed password for (?:invalid user )?(?P<user>\S+) "
    r"from (?P<ip>\d{1,3}(?:\.\d{1,3}){3}) "
    r"port (?P<port>\d+)"
)

Matches both for root and for invalid user admin variants.
Named groups (user, ip, port) extract the fields.
Accepted password lines do not match and are skipped.
Aggregating with a dictionary
python
counts[ip] = counts.get(ip, 0) + 1
users.setdefault(ip, set()).add(user)
counts maps each IP to its number of failures.
users maps each IP to the set of distinct usernames it tried. Many different usernames from one IP is a strong brute-force indicator.
Detection rule

An IP with 20 or more failed attempts (THRESHOLD in analyze_auth_log.py) is labelled SUSPECTED BRUTE FORCE.

**Configuration**

Setting	File	Default	Purpose
TOTAL_LINES	generate_auth_log.py	500	Number of log lines generated
ATTACKER_IPS	generate_auth_log.py	3 IPs	Simulated attacker addresses
random.seed(42)	generate_auth_log.py	42	Makes output reproducible
THRESHOLD	analyze_auth_log.py	20	Failures needed to flag an IP

**Limitations**

The threshold is a simple count with no time window. Real detection should consider failures within a short period (for example, 10 failures in 60 seconds).
It only inspects Failed password events, not other failure types such as Invalid user or public-key failures.
The IP regex does not validate octet ranges (it would accept 999.999.999.999). This is acceptable for system-generated logs.

**Possible improvements**

Add time-window detection to catch bursts.
Detect a successful login after many failures (possible compromise).
Export results to CSV or JSON.
Generate a firewall block list from flagged IPs.
Test against real sshd logs from a lab environment such as a Wazuh deployment.

**REAL WORLD SCENARIO**

### Real-World Scenario

In a real-world corporate environment, an organization may have hundreds of computers, servers, and network devices operating simultaneously. Monitoring each device individually and manually reviewing its log files can be time-consuming and make it difficult to identify potential security threats or technical issues. The Log Analyzer can be used as a centralized monitoring solution to simplify this process. By collecting logs from different devices through Syslog-ng or other supported log-forwarding mechanisms, the Analyzer automatically processes and examines incoming log entries to identify suspicious activities, repeated failed login attempts, unauthorized access attempts, unusual connection patterns, and system errors. For example, if someone repeatedly attempts to access a company server using incorrect credentials, the Analyzer can identify the repeated attempts, determine the source IP address, assign a severity level, and generate an alert for the IT team. Similarly, it can help identify potential port scanning activities, monitor device activity, and highlight systems that have stopped sending logs. Instead of manually checking multiple log files, IT administrators can use the Analyzer to receive organized findings and focus their attention on events that require investigation.

**Benefits and Practical Applications**

- Centralized Monitoring:** Monitor logs from multiple computers, servers, and network devices in one place.
- Automated Analysis:** Process incoming logs without manually opening and reviewing individual files.
- Suspicious Activity Detection:** Identify repeated login failures, unusual connection patterns, and other potentially malicious activities.
- Early Issue Identification:** Highlight potential security incidents and technical problems before they escalate.
- Source Identification:** Identify the IP address and device associated with a detected event.
- Severity Classification:** Categorize detected events according to their potential risk and importance.
- Improved IT Response:** Provide the IT team with relevant information to investigate and resolve issues more efficiently.
- **Reduced Manual Work:** Minimize the time spent reviewing raw log files and identifying important events.

**Overall Objective:** The purpose of the Analyzer is to transform raw system and network logs into meaningful, actionable information, helping organizations improve infrastructure visibility, identify potential security threats, reduce manual monitoring efforts, and enable IT teams to make faster and more informed decisions.
